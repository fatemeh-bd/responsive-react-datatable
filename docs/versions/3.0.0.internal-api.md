# 3.0.0 internal API typing clarification

## Internal API configuration types

Import InternalApiConfig, InternalApiPayload and InternalApiResponse from the package. Inline internalApiConfig values also provide completion.

| Option | Type | Behavior |
| --- | --- | --- |
| endpoint | string (required) | Relative path or absolute URL |
| baseUrl | string | Prefix for relative endpoints |
| method | "GET" or "POST" | Defaults to POST |
| headers | Record<string, string> | Request headers |
| defaultSortBy | string | Initial server sort field |
| sortType | "asc" or "desc" | Defaults to desc with defaultSortBy |
| customBody | CustomBody[] | Extra fields merged in order; later values win |
| payload | InternalApiPayload | Replaces the entire generated request, including customBody |
| onFetch | (response: InternalApiResponse) => void | Receives server body, not Axios wrapper |
| saveSearch | boolean (deprecated here) | Unused; use Table's saveSearch and tableName props |

CustomBody accepts application fields plus boolean noRefresh and isFilter metadata. These flags are not sent. Application field values are unknown and must be narrowed before reading. Response data is an array of records or null; recordsFiltered is a number, message is optional. InternalApiResponse<Row> can describe your server's row schema; Table callbacks keep unknown cell values because columns do not define a row schema. This is compile-time guidance, not extra runtime validation.

```tsx
import Table, { type InternalApiConfig } from "react-responsive-datatable-kit";
const api = {
  endpoint: "/api/people",
  method: "GET",
  customBody: [{ active: true, isFilter: true }],
  onFetch: response => console.log(response.recordsFiltered),
} satisfies InternalApiConfig;
<Table mode="internal" columns={columns} internalApiConfig={api} saveSearch tableName="people" />;
```
